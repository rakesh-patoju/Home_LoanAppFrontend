# Nestwell — Home Loan Management Frontend

Complete React frontend for `HomeLoan_Backend.zip`. Use the refreshed backend ZIP delivered with this frontend; it includes the direct-CORS fix tested below.

React · JavaScript · React Router · Axios · Bootstrap · Vite · local web fonts · Lucide icons

A responsive banking-style interface for CUSTOMER, LOAN_OFFICER and ADMIN. It uses the real backend APIs for every account, product, application, document, review and dashboard operation. There is no mock-data switch and no fake successful submission.

## Fastest way to run on Windows

The ZIP includes a built `dist/` folder and a small zero-dependency Node server. **No npm install or frontend build is required for this quick start.**

1. Install **Node.js 22.12 or newer** (Node 24 works). Verify `node --version`.
2. Start MySQL and the backend from the refreshed ZIP. Complete backend setup first if you have not already done so:

```powershell
# In the home-loan-backend folder, after creating the MySQL database:
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1
java -jar .\dist\home-loan-backend-1.0.0.jar
```

Run the backend setup script only once. If `config/local.properties` already exists, just start the JAR. The backend's default API port is 8080.

3. Open a **second** PowerShell window in the extracted `home-loan-frontend` folder:

```powershell
node .\scripts\serve.mjs
```

4. Open **http://localhost:5173**. Do not open `index.html` directly from File Explorer.
5. Use the emails and password from the backend's generated `DEMO-LOGINS.local.txt`.

| Role | Seeded email |
|---|---|
| Customer | customer1@homeloan.demo through customer5@homeloan.demo |
| Loan officer | officer1@homeloan.demo or officer2@homeloan.demo |
| Admin | admin@homeloan.demo |

Passwords are never embedded in the frontend. All seeded accounts use the random demo password generated by backend setup. Registration creates a new CUSTOMER account; staff accounts are managed by the admin.

The frontend and backend are **two separate processes**. Keep both terminal windows open. Close a server with Ctrl+C. The frontend does not contain MySQL credentials or a JWT signing secret.

## Develop or modify the source

```powershell
npm ci
npm run dev
```

Open http://localhost:5173. `npm ci` installs the exact tested versions from `package-lock.json`; it needs Internet access. The dev server deliberately fails if port 5173 is already occupied so it does not silently move to an unexpected origin. Stop the prebuilt server before starting Vite on the same port.

After source changes:

```powershell
npm test
npm run build
npm start
```

`npm start` is equivalent to `node scripts/serve.mjs` and serves the included production build. It does **not** rebuild your source. `npm run preview` is also provided and includes the API proxy.

For macOS/Linux, use the same Node/npm commands or `bash scripts/start.sh`.

## Backend connection and CORS

### Recommended default: same-origin API proxy

The browser calls `/api` on the frontend origin. The frontend server forwards requests to `http://127.0.0.1:8080`. Both Vite and the included production server support this forwarding, including JWT headers, idempotency headers, multipart uploads and binary downloads.

This means the normal setup does not require changing backend CORS configuration, whether you visit `localhost:5173` or `127.0.0.1:5173`. The server-to-server hop removes the browser's Origin header; the browser itself makes a same-origin request. JWT authentication and backend authorization remain enforced.

If the backend uses another port, copy `.env.example` to `.env` and update only `BACKEND_URL`:

```properties
VITE_API_BASE_URL=/api
BACKEND_URL=http://127.0.0.1:8081
```

Restart the frontend server. With the included server and `/api` mode, changing BACKEND_URL does **not** require a frontend rebuild. Use the backend **origin**, without `/api`, for BACKEND_URL.

### Optional: direct cross-origin API calls

Use the refreshed backend ZIP. The earlier backend registered its CORS bean under a name Spring Security did not automatically pick up; that is corrected and covered by two regression tests. The default proxy also works with the earlier backend.

For a direct connection from browser to Java:

```properties
VITE_API_BASE_URL=http://localhost:8080/api
```

Restart Vite, or run `npm run build` again before serving the production build. Open the frontend specifically at **http://localhost:5173**, which the corrected backend allows. `VITE_*` variables are embedded at build time; they are not secrets.

The backend's default CORS origins are `http://localhost:5173,http://localhost:3000`. If you intentionally use a different frontend origin in direct mode, set its `ALLOWED_ORIGINS` environment variable to an exact comma-separated list and restart Java. Do not add spaces around origins. Do not use wildcard credentials. There are no cookie-based login sessions in this demo.

### Change frontend port

For the included local server:

```powershell
$env:FRONTEND_PORT='5174'
node .\scripts\serve.mjs
```

The default same-origin proxy continues to work. For direct-CORS mode, add the new origin to backend ALLOWED_ORIGINS. FRONTEND_PORT controls the included Node server; Vite uses the port in the npm script.

## Implemented pages and features

**Public:** home, about, live loan products, login, customer registration.

**Customer:** dashboard, profile, eligibility calculator, three-step application form, paginated application list, application details, five document categories, replacement uploads, authenticated downloads and chronological status history.

**Loan officer:** dashboard, assigned application list, customer details, document verification/rejection, application remarks, additional-document requests, approval/rejection and status tracking.

**Admin:** dashboard, all applications, officer assignment/reassignment, customer edits and account enable/disable, officer creation/edits, product creation/edits/activation, sanction and demo disbursement.

## Workflow demonstration

1. Log in as a customer. Explore products or calculate eligibility.
2. Start a new application. Choose a product, enter financial details and review before submitting.
3. Open Documents and upload a fictional file under each category. `samples/fictional-demo-document.pdf` is included for testing.
4. Find the assigned officer in the application Overview. Log out and log in as that officer. Use the admin's officer list if you need to match names and emails.
5. Open the assigned application, start review, and review the latest document in each category. Approval is disabled until all five latest documents are verified; the backend independently enforces the same rule.
6. Approve the application. Only admin can record sanction and disbursement.
7. Log in as admin, record sanction, then demo disbursement. No money is transferred.
8. Return as the customer and read the activity history.

To request additional evidence, choose “Request documents” and explain what is needed. The customer uploads a replacement. The replacement starts PENDING and must be verified again. Earlier files remain available under Previous uploads.

## Important behavior

- Tenure is sent to the backend in **months**, not years.
- Eligibility includes existing EMIs plus the estimated new EMI. It is a preliminary estimate, not actual approval.
- Submitted loan details cannot be edited. Profile changes do not rewrite past application financial snapshots.
- Application submission generates an idempotency key and keeps it for retrying the same body, including after a timeout. The backend also rejects identical active applications.
- Table search filters the **current page**; the UI states this explicitly. Pagination and sorting are server-side.
- Access tokens are stored in `sessionStorage` for this local demo and cleared on logout/expiry/401. Do not treat browser route guards as a security boundary; all authorization remains in Java. Logout does not revoke an issued JWT server-side.
- Downloads use Axios with the bearer header and a Blob; a plain unauthenticated link is not used.
- Multipart Content-Type is set by the browser, so file boundaries are correct.
- Fonts and illustrations are bundled locally; the interface does not require a font CDN or remote image service.
- Officer disabling can fail with a useful backend message if there are open assigned applications. Reassign them first.
- Approved dashboard counts include sanctioned and disbursed applications, matching the backend.

## Troubleshooting

| Symptom | Fix |
|---|---|
| “node is not recognized” | Install Node.js 22.12+ and reopen PowerShell. |
| PowerShell blocks npm.ps1 | Use `npm.cmd ci`, `npm.cmd run dev`, etc., or run the quick-start `node scripts/serve.mjs`. No permanent execution-policy change is needed. |
| Loan service unavailable / 502 | Start MySQL and Java; check backend startup logs and BACKEND_URL. |
| Port 5173 already in use | Close the other frontend process or choose FRONTEND_PORT for the included server. |
| CORS error in direct mode | Use localhost:5173, verify exact ALLOWED_ORIGINS and restart Java. Default proxy mode needs no CORS edits. |
| Login rejected | Use the backend-generated demo password; the MySQL password is not a web login password. |
| 401 after restarting Java | Log in again; a changed JWT key invalidates older tokens. |
| 403 application details | Log in as the owning customer, assigned officer or admin. |
| Approval unavailable | Verify the latest upload in every required category; start UNDER_REVIEW first. |
| New source changes are not visible | Run npm run build before using npm start; or use npm run dev for development. |
| Browser refresh on a detail URL fails with another hosting server | Configure an SPA fallback to index.html and an /api proxy. The supplied server already includes both. |
| Upload rejected | Use PDF/JPG/PNG, maximum 5 MB, and match actual file content to extension. |
